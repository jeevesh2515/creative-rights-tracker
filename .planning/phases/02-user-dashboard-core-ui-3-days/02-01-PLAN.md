<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client→API | Frontend requests /api/revenue, /api/projects without auth validation visible to client |
| API→Database | Backend validates user permissions before returning data |
| Blockchain→Display | Contract data displayed without verification that user owns that data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | /api/revenue response | Mitigate | Add response integrity check: verify API response matches expected schema (zod validation on client) |
| T-02-02 | Information Disclosure | Dashboard displays all transactions | Mitigate | Verify auth token present in API request headers; add row-level security check on API |
| T-02-03 | Denial of Service | Large transaction list crashes UI | Mitigate | Implement pagination (50 items/page), avoid rendering >1000 rows without virtualization |
| T-02-04 | Elevation of Privilege | User sees another user's earnings | Accept | Backend API enforces user_id filtering; frontend displays whatever API returns |

</threat_model>
