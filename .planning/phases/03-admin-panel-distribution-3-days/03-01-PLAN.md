<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client→AdminPage | Only authenticated users with admin role allowed to view admin page |
| AdminPage→Supabase | Admin actions (user updates, distribution logging) must pass authentication check |
| AdminPage→SmartContract | Distribution calls originate from verified admin user |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | Role Check | Mitigate | Verify user?.role === 'admin' before rendering AdminPage; check on every page load (not just mount) |
| T-03-02 | Tampering | Tab Navigation | Accept | Tab switching is client-side, purely UI; non-persistent (no state saved on backend) |
| T-03-03 | Repudiation | Audit Log | Mitigate | Every admin action MUST log to Supabase audit table with user_id, action, timestamp |
| T-03-04 | Information Disclosure | AdminLayout | Mitigate | Only render admin UI if role === 'admin'; non-admins see "Access Denied" |
| T-03-05 | Denial of Service | Admin Page Load | Accept | Page load may be slow with many users; pagination/lazy-loading deferred to phase 3.2 |
| T-03-06 | Elevation of Privilege | User Management | Mitigate | Role change actions must be logged; only admins can modify roles via database constraint |

</threat_model>
