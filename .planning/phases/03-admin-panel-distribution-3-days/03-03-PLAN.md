   ```typescript
   useEffect(() => {
     const fetchLogs = async () => {
       setIsLoading(true);
       try {
         // Fetch from Supabase activity table filtered by date range
         const { data, error } = await supabase
           .from('activity')
           .select('*')
           .gte('created_at', dateRange.from.toISOString())
           .lte('created_at', dateRange.to.toISOString())
           .order('created_at', { ascending: sortOrder === 'asc' })
           .range((currentPage - 1) * pageSize, currentPage * pageSize);

         if (error) throw error;
         setLogs(data || []);
       } catch (err) {
         toast.error('Failed to fetch audit logs');
       } finally {
         setIsLoading(false);
       }
     };

     fetchLogs();

     // Optional: Real-time subscription (show new logs as they arrive)
     const subscription = supabase
       .channel('audit_logs')
       .on('postgres_changes', 
         { event: 'INSERT', schema: 'public', table: 'activity' },
         (payload) => {
           setLogs(prev => [payload.new, ...prev.slice(0, pageSize - 1)]);
         }
       )
       .subscribe();

     return () => subscription.unsubscribe();
   }, [dateRange, sortOrder, currentPage, actionFilter]);
   ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client→/api/admin/users | User management requests must originate from authenticated admin users |
| /api/admin/users→Supabase Users | Allocation updates immutable once persisted; audit trail mandatory |
| /api/admin/users→Supabase Audit | Every user allocation change logged with admin_id and timestamp |
| Audit Log→Supabase Activity | Audit log read-only from frontend; only admins can view |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-13 | Spoofing | /api/admin/users | Mitigate | Verify admin role server-side on GET and PUT; check session token |
| T-03-14 | Tampering | User Allocation | Mitigate | Validate allocation_percentage (0-100) server-side; immutable after update |
| T-03-15 | Repudiation | Allocation Audit | Mitigate | Every allocation change generates audit log with admin_id, timestamp, old value, new value |
| T-03-16 | Information Disclosure | Audit Log | Mitigate | Only admins can fetch audit logs; mask user PII if necessary (show user_id, not password) |
| T-03-17 | Denial of Service | User List Load | Accept | Large user lists may be slow; pagination (10 per page) mitigates client-side overload |
| T-03-18 | Elevation of Privilege | Role Update | Mitigate | Allocation updates do NOT change user role; role changes forbidden in this endpoint |

</threat_model>
