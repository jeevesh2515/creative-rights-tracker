# Phase 06-02: Performance Testing & Optimization

## Objective

Measure and optimize performance to meet launch targets: <2s dashboard load, smooth interactions, stable real-time updates.

## Tasks

### Task 1: Lighthouse Performance Audit

Run Lighthouse on key pages:

```bash
# Admin dashboard
npm run build
npm run start
# Open http://localhost:3000/admin
# Run Lighthouse (DevTools)

# User dashboard
# Open http://localhost:3000/dashboard
# Run Lighthouse

# Target scores:
# - Performance: ≥80
# - Accessibility: ≥95 (from Phase 5)
# - Best Practices: ≥90
# - SEO: ≥90
```

**Document:**
- Current scores per page
- Bottlenecks identified
- Optimization recommendations

### Task 2: Load Time Benchmarking

1. **Dashboard Load Time**
   - Measure Time to First Contentful Paint (FCP)
   - Measure Largest Contentful Paint (LCP)
   - Complete page load time
   - Target: <2s LCP

2. **Real-time Data Updates**
   - Measure Supabase subscription latency
   - Event listener to UI update time (target: <1s)
   - Multiple concurrent updates (5+ simultaneous)

3. **Transaction Submission**
   - Gas estimation request time (target: <1s)
   - Transaction submission latency
   - Confirmation polling responsiveness

**Tools:**
- Chrome DevTools Network/Performance tabs
- Web Vitals (use next/analytics)
- Custom console.time() measurements

**Artifacts:** PERFORMANCE-BASELINE.md

### Task 3: Bundle Size Analysis

1. **Static Bundle**
   ```bash
   npm run build
   # Review build output size
   # Identify large chunks
   ```

2. **Code Splitting**
   - Verify dynamic imports working (lazy-loaded components)
   - Check if analytics components code-split to lazy chunks

3. **Image Optimization**
   - Verify next/image used for responsive images
   - Check PNG/SVG optimization
   - WebP fallback configured

**Artifacts:** BUNDLE-ANALYSIS.md

### Task 4: Real-time Subscription Performance

1. **Supabase Load Test**
   - Connect multiple clients (5+)
   - Trigger events (balance updates, audit log entries)
   - Measure latency per client
   - Check for subscription dropping

2. **Event Listener Stability**
   - Run event listeners for 10+ minutes
   - Verify no memory leaks
   - Check for reconnection issues

3. **Polling Mechanism**
   - Gas price update polling (10s interval)
   - Transaction confirmation polling (5s interval)
   - Verify no runaway timers

**Artifacts:** REALTIME-PERFORMANCE.md

### Task 5: Optimization (If Needed)

If performance targets not met:

1. **Code Splitting**
   - Dynamic import for admin-only components
   - Lazy load charts (Recharts can be heavy)

2. **Caching**
   - Add ISR (Incremental Static Regeneration) for dashboard
   - Cache API responses: gas prices (30s), user data (1min)

3. **Image Optimization**
   - Convert any PNG to WebP
   - Add image sizes prop to next/image

4. **Database Optimization**
   - Add indexes to frequently queried tables (activity, users)
   - Optimize audit log query (pagination)

**Commit:** If optimizations made

## Must-Haves

- ✓ Lighthouse Performance ≥80
- ✓ Dashboard LCP <2s
- ✓ Real-time updates <1s latency
- ✓ No memory leaks in long-running processes
- ✓ Stable Supabase subscriptions

## Verification

- Lighthouse scores documented
- Load time baselines captured
- Real-time latency acceptable
- No performance regressions vs previous phases
