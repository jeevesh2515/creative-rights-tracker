# Phase 06-03: UAT, Launch Checklist & Deployment

## Objective

Validate all user workflows, prepare deployment checklist, and deploy to production on testnet.

## Tasks

### Task 1: User Acceptance Testing (UAT)

Complete end-to-end scenarios with demo data:

#### Scenario 1: User Earnings Dashboard
1. User logs in with test Clerk account
2. Dashboard loads with revenue data (from demo seed)
3. Verify accuracy of:
   - Total distributed amount
   - Per-project breakdown
   - Transaction history
4. Check mobile responsiveness (test on iPhone simulation)
5. Verify real-time updates (if balance updates during test)

**Expected Outcomes:**
- Dashboard loads in <2s
- All data displays accurately
- Mobile layout responsive
- No console errors

#### Scenario 2: Revenue Distribution (Admin)
1. Admin logs in
2. Navigates to Distributions tab
3. Creates new distribution:
   - Selects project
   - Enters total amount (test with 10.5 ETH)
   - Adds 2-3 recipients with percentages
   - Verifies allocation preview sums to 100%
4. Submits distribution
5. **Transaction Submission:**
   - Gas fee displays correctly
   - Verifies signature with MetaMask (testnet)
   - Transaction status shows pending
   - On-chain confirmation occurs
6. **Real-time Updates:**
   - Audit log updates immediately
   - User earnings update when confirmed
   - Balance reconciliation triggers

**Expected Outcomes:**
- Distribution created in <5 seconds
- Gas fee accurate (vs etherscan)
- Transaction confirms on testnet
- All updates propagate without manual refresh

#### Scenario 3: Audit Log Verification
1. Admin views Audit tab
2. Verifies recent distribution action logged
3. Checks immutable log cannot be edited
4. Tests pagination (if >10 entries)
5. Checks timestamps accurate

**Expected Outcomes:**
- Log entry appears immediately
- All fields populated correctly
- No ability to modify/delete
- Pagination works if needed

#### Scenario 4: Error Handling
1. Analytics fail to load (simulate network error)
   - Verify skeleton state shows
   - Skeleton clears when data loads
   - No console errors
2. User balance exceeds available amount
   - Form validation prevents submission
   - Error message clear and helpful
3. Network disconnects during transaction
   - Status shows "pending" not "failed"
   - User can retry
4. MetaMask wallet rejected transaction
   - Clear error message
   - User can retry with new params

**Expected Outcomes:**
- Graceful error handling
- Clear user messaging
- No silent failures
- Recovery paths available

### Task 2: Accessibility Verification

Run accessibility checklist (from Phase 5):

1. **Keyboard Navigation**
   - Tab through all admin forms
   - Verify logical tab order
   - Verify no keyboard traps
   - Expect: Can reach all buttons/inputs without mouse

2. **Screen Reader Testing** (optional, or manual check)
   - Use browser accessibility inspector
   - ARIA labels present on forms/charts
   - Table structure announced correctly
   - Error messages announced as alerts
   - Expect: All important content discoverable

3. **Lighthouse Accessibility Score**
   - Re-run Lighthouse accessibility audit
   - Target: ≥95
   - Document any issues

### Task 3: Bug Triage & Severity Classification

During UAT, document any issues found:

**Critical (Blocks Launch):**
- Security vulnerabilities
- Data loss/corruption
- Complete feature failure
- Crashes on core workflow

**High (Fix Before Launch):**
- UI layout broken on mobile
- Transaction fails to submit
- Real-time updates delay >5s
- Audit logs not recording

**Medium (Fix Post-Launch):**
- Minor UI polish
- Console warnings (non-blocking)
- Performance optimizations
- Non-core feature gaps

**Low (Backlog):**
- Future enhancement ideas
- Nice-to-have improvements
- Documentation updates

**Process:**
- List all bugs found during UAT
- Assign priority
- Fix critical/high issues before deployment
- Document low/medium for next milestones

**Artifacts:** UAT-RESULTS.md with findings and resolutions

### Task 4: Deployment Preparation

#### 4a. Environment Configuration

1. **Vercel Project Setup**
   - Create Vercel project (linked to GitHub)
   - Add environment variables:
     ```
     NEXT_PUBLIC_SUPABASE_URL=<prod-supabase-url>
     NEXT_PUBLIC_SUPABASE_ANON_KEY=<prod-anon-key>
     CLERK_SECRET_KEY=<prod-clerk-key>
     NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=<prod-clerk-key>
     NEXT_PUBLIC_INFURA_KEY=<testnet-infura-key>
     NEXT_PUBLIC_CHAIN_ID=11155111  # Sepolia testnet
     ```
   - Verify no secrets exposed in build logs

2. **Production Database**
   - Verify Supabase production project exists
   - Run migrations on production DB
   - Seed demo data to production
   - Verify backups configured

3. **Monitoring Setup**
   - Create Sentry project for error tracking
   - Add Sentry DSN to env vars
   - Configure alert thresholds (emails on critical errors)
   - Set up Vercel Analytics

#### 4b. Contract Configuration

1. **Testnet Deployment**
   - Verify RevenueRights.sol deployed to Sepolia (or chosen testnet)
   - Verify RevenueSplitter.sol deployed
   - Update contract addresses in .env
   - Verify ABI files match deployed contracts

2. **Wallet Setup**
   - Set up MetaMask on Sepolia testnet
   - Fund admin wallet with test ETH (~1 ETH)
   - Fund distribution contract with test ETH (~5 ETH)

#### 4c. Authentication Setup

1. **Clerk Production**
   - Verify Clerk production environment configured
   - Set OAuth providers (Google, GitHub, etc.)
   - Set up email verification
   - Configure role-based permissions

2. **Admin User**
   - Create admin user in production Clerk
   - Assign admin role
   - Verify can access /admin routes
